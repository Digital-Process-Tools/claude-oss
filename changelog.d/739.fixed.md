- `doctor`'s supertool op inventory check (#582) reported `all 18 op(s) … resolve` while 21 real
  supertool ops named in this plugin's own `commands/`, `skills/` and `agents/` text — including
  `gh-issue-create`, `gh-run`, `gh-job` and `gh-pr` — were invisible to it: every one of them sits
  in `skills/manager/SKILL.md`'s op table, written as a bare cell with no `supertool` word in front
  of it, which the existing call-shaped derivation never matches by design (#726 measured that
  dropping that requirement derives eighteen English words out of ordinary prose). The op table is
  now parsed as a second, narrower source, anchored on its own heading the way
  `scripts/ranking_table.py` reads the ranking table out of the same file, rather than swept as
  free text — a bare cell is only accepted when it is compound-shaped (`gh-branch`), and a
  colon-argument cell (`gh-run:N`) is always accepted, so a plain word in the same column's own
  prose (`base`) is not derived as an op. A bare op-shaped word outside the table entirely — such
  as `watch`, which also names a supertool preset elsewhere in this plugin's own text — is still
  not derived; this is a deliberately narrow, structured-source widening, not a general sweep for
  backticked op names (#739).
