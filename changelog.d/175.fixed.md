- The release gate has an arm for an audit finding that arrived without a ranking row. It blocked on
  membership in a blocking row — a positive test, so a finding with no row at all was in no blocking
  row, the exception never fired, and the two-round cap carried it forward and shipped it. A rank
  that could not be computed rendered exactly like a rank that is not blocking. The two rowless
  answers the audit agents already define are now answered separately, because collapsing them
  re-creates the same defect a layer down: `unranked` — classified and no row fits — blocks the tag
  until it is ranked, and ranking it, or earning it a row, is the way past; `could not rank` — the
  table never reached the agent — is re-dispatched with the table in the payload and, if it comes
  back the same way, is `could not run` and stops the release. Neither is carry-forward material by
  omission (#175).
