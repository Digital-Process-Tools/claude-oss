- Dispatch selection (`select_issues.py`) no longer drops a candidate whose declared files overlap
  the fleet's held set -- the `lane-collision` disposition and its outright exclusion are gone.
  The candidate stays `eligible`, and its `overlap` field names the held files and, when the fleet's
  own held map carries it, which lane already holds each one. `lane_setup.py`'s own
  `--derive-held` receipt keeps the same underlying `blocked` verdict state (unchanged, still
  documented in `skills/manager/phases/dispatch.md`) but no longer renders it as `verdict : BLOCKED`
  -- it now prints `verdict : OVERLAP -- ... -- information, not a block`, so a same-lane collision
  a maintainer already diagnoses correctly (#1526 vs lane #1499, both `lane-prose`) is not also
  read as an instruction to stop. Closes #1528.
