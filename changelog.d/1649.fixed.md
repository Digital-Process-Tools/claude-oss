- `oss:doctor`'s `on-default` write-then-commit path never checked whether the default branch was
  actually protected before committing onto it -- a repo requiring pull-request review can only
  receive that commit through a branch-protection bypass push. Its own `--findings` run could not
  have caught this either: the branch-protection check reports `OK` when a branch IS protected,
  and `--findings` suppresses `OK` lines, so the one line saying "stop" was exactly the line the
  spawn's own diagnostic pass never showed it. `on-default` now calls
  `doctor_check_branch_protection.branch_protection_state` directly before writing anything, and
  reports `could-not-repair: main is protected -- <detail>` (or the `could-not-tell` equivalent)
  instead of writing then committing when the branch is protected or its protection state cannot
  be confirmed (#1649).
- `/oss:run`'s step 1 `oss:doctor` spawn now pins `run_in_background: false`, the one remaining
  bare `Agent(...)` call `#1586`'s own fix did not reach (#1649).
