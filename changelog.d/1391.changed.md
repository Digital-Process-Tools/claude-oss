- Changed (#1391): `skills/manager/SKILL.md` now declares `user_invocable: false`. The manager
  skill is the loop's spine, loaded as a library by `commands/tick.md` and `commands/release.md` via
  `Skill(manager)`; it is not an entry point, and invoking it directly loaded the whole spine into
  the invoking session, defeating the per-tick context discard the sub-manager exists for. It no
  longer appears in the slash picker as `/oss:manager`. Whether `Skill(manager)` still resolves for
  both callers with the flag false could not be established from inside the developer lane's session
  -- no installed skill anywhere on this machine carries `user_invocable: false` to test the harness
  against, and flipping the installed plugin cache's own copy to find out would have been a write
  outside the lane's worktree. A new test, `tests/test_manager_not_user_invocable_1391.py`, pins the
  frontmatter value and that both callers still name `Skill(manager)`; it cannot exercise harness
  resolution either.
