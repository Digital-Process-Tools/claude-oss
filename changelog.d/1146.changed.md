- Changed `select_issues.select_fleet` to return one group per declared lane label
  (`.oss.json`'s `labels.lanes`) instead of one partition of the whole board (#1146). On the live
  38-issue board the old shape returned 18 groups for a tick that dispatches at most five lanes --
  most of them computed, rendered, and never used, and handing an agent 18 options invited it to
  re-rank them instead of doing the veto it should be doing. "One group per lane" means exactly
  one: a maintainer round found the first cut still returning every group a lane's own candidates
  could form (23 groups across five lanes plus the no-lane-label bucket, measured live), so each
  real lane's `groups.groups` is now truncated to its single best-ranked group -- lead plus up to
  two companions by the existing adjacency rules -- before bodies are attached, since a lane runs
  one developer at a time and a lane's second, third and fourth groups would only be recomputed
  next tick against a board that has moved. Nothing is lost: every eligible issue in the lane still
  appears in its `candidates` list, and `ungrouped` (declares no files, #267) is untouched -- the
  cap removes a group's number, not an issue's visibility. `select()` itself is unchanged, called
  once per lane label with its existing `lane_label` filter (#1078) narrowing candidate generation.
  An issue carrying none of the declared lane labels does not vanish now that iteration is
  label-driven: it (and a `labels.lane_other` issue, which names no subsystem of its own -- #1130)
  surfaces under the new `NO_LANE_LABEL_KEY` bucket, run through the identical `select()` machinery
  as any declared lane -- never a sixth lane, since nothing disjoint-by-construction backs it, and
  never silently dropped. A lane label with no eligible issue still gets its own key with a stated
  `none-available`, never a missing one. The no-lane-label bucket is deliberately left uncapped for
  now, pending a maintainer decision on whether it should cap the same way or return no group at
  all, since #1130 already requires a `lane-other` issue to dispatch solo, never bundled.
