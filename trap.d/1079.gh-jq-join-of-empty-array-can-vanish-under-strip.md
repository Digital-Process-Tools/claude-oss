Writing `_gh_unlabelled_issue_counts` in `scripts/statusline.py` (#1079), the same
paginated-REST-plus-cross-check-against-total shape `_gh_external_issue_count` already
uses, but for a per-issue list of label names rather than a single non-empty string
field (`author_association`).

`gh api --jq '... | [.labels[].name] | join(",")'` prints one line per issue, and an
issue with zero labels prints an empty line -- which is correct, real data (one issue
read, it carries no labels), not a sign that nothing was read. `_run()` (the module's
own subprocess wrapper) calls `.strip()` on the whole blob before returning it, and
`.strip()` does not know the difference between trailing whitespace and a trailing
*empty line that is itself a real row of data*. If the LAST open issue on the page
happens to carry no labels, its blank line sits at the very end of the output and gets
eaten by `.strip()` along with the real trailing newline -- so `out.split("\n")` comes
back one line short of `total`, and the cross-check (which exists specifically to catch
a truncated/racing page) fires a false positive and folds a completely successful read
into `None`.

Caught by writing a fixture for it directly (`_run` returning
`"L:priority-high\nL:"` for `total=2`) rather than by any generic property test --
nothing about "assert result is not None for two well-formed rows" would have
suggested trying the empty-row-last ordering. The general shape: whenever `_run`'s own
`.strip()` sits between a `--jq` call and a `len(lines) == total` cross-check, an
empty line is legitimate output as long as it is not also boundary whitespace, and the
two are indistinguishable to `.strip()`. Fixed here by prefixing every printed line
with a non-empty marker (`"L:"`) so no real line is ever whitespace-only; a caller
that does not need per-line structure could also just avoid `--jq` output shapes that
can print an empty line in the first place.

Confirmed by running the fixed function against both a fixture with the empty issue
first (already passed before the fix, since only a *trailing* empty line is at risk)
and one with it last (failed before the `"L:"` prefix, passed after).
