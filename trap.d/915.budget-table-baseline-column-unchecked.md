# Nothing compares CLAUDE.md's "measured (baseline)" column to the files it names

Observed 2026-09-03 while measuring what a developer lane loads before its first tool call.

`agents/developer.md` measures **89,144 B** on disk. CLAUDE.md's agent budget table records its
baseline as **83,014 B** against a 91,300 B budget. The stale number reads as 9% headroom; the real
one is **2,156 B, 2.4%**. A lane author trusting the table would think there is room for a page of
new instruction where there is room for about forty lines.

## Why nothing caught it

Both budget tables in CLAUDE.md have two numeric columns and only one of them is checked.

- `tests/test_claude_md_budget_table_709.py` holds the agent table against `agent_budgets.BUDGETS`,
  and `tests/test_claude_md_phase_budget_table_725.py` holds the phase table against
  `skill_phases.DOCUMENTS`. Both compare the **budget** column, which is the one that already lives
  in code.
- The **measured (baseline)** column has no source in code. It is a reading somebody took by hand at
  some commit, and it drifts every time the file changes, silently, in the direction that makes the
  headroom look larger than it is.
- `scripts/agent_budgets.py` fails the build when a file crosses its budget, so the *ceiling* is
  enforced. Nothing fails when the table's own account of where the file sits is wrong.

That is the repository's own defect class landing on its own instrumentation: a column that renders
a stale reading identically to a fresh one, with no third state saying "this was measured at a
commit that is not this one".

## Same shape, already recorded twice

CLAUDE.md already documents two instances and treats each as a one-off:

- The `dispatch.md` row that produced #675 -- a measured byte count that meant different things on
  different checkouts.
- The total-bytes sentence, which CLAUDE.md admits in its own prose had "already gone stale by the
  time `dispatch.md`'s own row moved for #880", undercounting the table by 3,580 B, with the
  instruction to "sum the table's own column the next time a row changes, rather than editing this
  sentence by hand". That instruction is a request for a human to do arithmetic reliably, forever,
  which is the shape of rule this repository generally refuses to rely on.

Three instances of one thing. The baseline column, the total sentence, and the per-row drift are the
same defect: hand-copied measurements of files that change, with a test suite that checks the
budgets beside them and not the measurements.

## What is not decided here

Whether the fix is a test that recomputes the baseline column, dropping the column entirely (the
budget and a pass/fail are what a reader acts on -- the baseline is only useful as headroom, which
is derivable), or generating both tables into CLAUDE.md at build time. Generation conflicts with
CLAUDE.md being hand-curated and the loop not writing to it, so that is not a free choice.

Related: [[915.developer-floor-dominates-lane-cost]], which is why the headroom on this particular
file matters more than on the others -- `developer.md` is re-sent on every turn of every lane, one
to three lanes per tick.
