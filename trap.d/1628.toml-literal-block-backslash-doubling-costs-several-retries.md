Writing scripts/worktree_reap.py and its test file via supertool paste/edit with TOML
triple-single-quoted literal blocks, I repeatedly mis-escaped backslashes and apostrophes.

What happened: a TOML literal string processes no escapes at all, so whatever bytes are
typed land on disk verbatim. Coming from writing Python source where a backslash-n inside a
Python string literal is a one-character escape, my reflex was to double the backslash as
though the TOML layer would also interpret an escape -- it does not, so this wrote two
literal backslash characters plus an n into the Python source, which is wrong. Separately, I
habitually escaped apostrophes inside prose docstrings even though a TOML literal string
needs no escaping for a lone apostrophe -- these were harmless but unnecessary and got
flagged by the refusal each time they collided with an actually-legitimate backslash
elsewhere in the same payload.

Cost: at least 4 separate paste/edit refusals across this lane, each costing a full
round-trip to read the refusal message, decide per-occurrence whether the backslash run was
"meant AS WRITTEN" or "meant HALF", and either fix the content or add the
literal_backslashes escape hatch. One payload (scripts/worktree_reap.py's own docstring)
needed the whole-field exemption because it mixed a real Windows-path backslash example
(meant literally, inside a comment) with nothing else needing correction.

How confirmed: each refusal message named the exact line/column of the offending run and
gave two opposite fixes; picking correctly on the first read (rather than guessing) avoided
compounding the mistake, but still cost the round-trip either way.

Possible angle for a rule: something that primes "a TOML literal block does zero escape
processing, write the exact bytes you want on disk" more forcefully before the first write
in a session that touches Python source (where the single-vs-double-backslash distinction
matters) might have prevented at least 2 of the 4 refusals. Uncertain whether this is common
enough across lanes to be worth a dedicated rule -- logging it rather than deciding.
