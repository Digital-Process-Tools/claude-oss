Gate-3 audit (v0.42.0 round 1, range v0.41.0..HEAD). `scripts/statusline.py`
(~lines 613-619, #1692) sets `since_floor = len(commits) >= window`, treating
a short commit log as proof the release-boundary commit was actually reached.
In a shallow clone, `git log` stops at the graft point rather than the true
boundary, so a truncated count can satisfy `>= window` and render as an exact
figure (e.g. `rel 50/?` with no `+` marker) instead of the honest "at least
N, could be more". Before #1692 this state rendered `?`; `scripts/
release_delta.py` already refuses to operate on a shallow clone for exactly
this reason. Reasoned, not observed against a real shallow clone. What would
settle it: an `is-shallow-repository` check folded into the `since_floor`
computation.
