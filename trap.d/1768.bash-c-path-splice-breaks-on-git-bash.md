A test that builds a `bash -c` script and splices a stub directory into PATH inside the script
text -- `'PATH="{}:$PATH"'.format(bin_dir.as_posix())` -- works on every POSIX leg and fails on
Windows: `as_posix()` gives a drive-letter path (`C:/...`), and Git Bash splits PATH at the colon after the drive
letter, so the stub (`claude` here) is never found and the call exits 127.

Where: `tests/test_workspace_plugin_enabled_1768.py`, first push of PR #1769. Cost: one CI round,
3 failures on `pytest (windows-latest, 3.12)`.

Fix that worked: pass PATH through the child's environment instead, joined with `os.pathsep`
(`;` on Windows), which Git Bash converts at startup -- exactly what `tests/launcher_env.py`
already does for the launcher suites. Nothing pointed a new test file at that helper; I found it
only after the leg went red.

Same PR, same round, different leg: `Path.write_text(..., newline="\n")` is Python 3.10+, and the
floor is 3.9, so `pytest (ubuntu-latest, 3.9)` failed 10 tests with `TypeError: write_text() got
an unexpected keyword argument 'newline'`. `write_bytes(body.encode("utf-8"))` works on 3.9 and
keeps LF for a shebang on Windows too. No local 3.9 interpreter to catch it before pushing.
