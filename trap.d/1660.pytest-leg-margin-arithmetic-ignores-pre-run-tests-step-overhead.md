While fixing #1660 (the posthang diagnostic's delay firing after the job's own
timeout-minutes cap instead of before), an oss:auditor spawn reviewing the fix flagged an
open question about a design decision that predates this fix (from #1658/#1659): every
margin calculation in tests/test_pytest_leg_timeout_1658.py and the new
tests/test_posthang_diagnostics_1660.py::test_dump_delay_fits_inside_the_jobs_own_margin
computes `margin = timeout_minutes*60 - OBSERVED_WORST_CASE_SUITE_MINUTES*60`, treating
pytest's own self-reported "N passed... in Xs" summary-line duration as directly
commensurable with the GitHub Actions job's total wall-clock timeout-minutes cap.

But `timeout-minutes` on a job measures from job start, which includes checkout,
setup-python, the Windows Defender exclusion step, and `pip install` -- none of which are
counted in pytest's own "in Xs" line. The workflow's own #1658-era comment
(.github/workflows/tests.yml, around the timeout-minutes: 30 line) already says this
overhead is what pushes total wall time past the ceiling, yet none of the margin
arithmetic in either test file has a term for it.

If that overhead is non-trivial (#1196 measured ~44s just for the Python 3.9 tool-cache
case on a different leg; the windows-latest/3.12 leg specifically doesn't pay that install
cost since 3.12 is baked into the image, so its own overhead is presumably smaller, but it
has never been measured and isolated), the real margin before a job hits its cap is
SMALLER than what these tests currently compute -- meaning the already-thin ~26.9s
margin figure from the third #1660 occurrence could itself be an overstatement of the
true headroom.

Not fixed here: settling this needs either an instrumented CI run that times each step
separately (e.g. `::group::`/timing markers around checkout/setup/install on the
windows-latest/3.12 leg specifically) or a comparison of GitHub's own per-step timing in
the Actions UI for a real run of this leg. Neither is something a single lane can produce
locally; it needs a live CI round.

How confirmed: reasoned by the auditor from reading tests/test_pytest_leg_timeout_1658.py's
own docstring alongside .github/workflows/tests.yml's #1658-era comment; not independently
measured against a real job run's own step timings.
