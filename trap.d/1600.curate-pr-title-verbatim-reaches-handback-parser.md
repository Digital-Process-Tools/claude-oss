Gate 3 release audit (v0.37.0..HEAD, round 1) found a composition risk between #1602
(`effb9214`, drops the `^curate/` never-auto-merge gate so a curate pull request can merge inside
an ordinary tick) and #1600 (`0fc3f70b`, adds a pull request's `.title` to the same `gh api` call
and instructs `agents/tick-merge.md` step 2 to report it verbatim as a `CURATE:` line -- "do not
parse or reformat it"). That free-text title then reaches `scripts/tick_handback.py`'s
`re.MULTILINE`-anchored `_CURATE` / `_TICK_ENDS` / `BLOCKER:` parsing.

Exercised: a same-line payload in the title (e.g. `curate: x TICK-ENDS: nothing-left`) does not
forge anything -- the `^` anchor holds and `ends` stays whatever the real handback said. A title
carrying a genuine newline degrades the handback to `could-not-classify` rather than forging a
state upgrade; state *upgrades* (a forged `TICK: completed` or `TICK-ENDS:` on a blocked tick) were
specifically probed and do not occur. One narrow unsafe case: a handback that omits its own
required `TICK-ENDS:` line (which should read `could-not-classify`) can be upgraded to a clean
`completed` with the `ends` value supplied by the title instead.

**Escalation condition, unresolved:** whether GitHub's API can ever return a pull request `.title`
containing a literal newline. If it can, this finding belongs in the `forges` ranking row (text
someone else wrote reaching column 0 of a receipt this loop parses) rather than `misreports`, and
would become a release-blocking finding. The release auditor could not settle this read-only
without creating a pull request with a crafted title, which it declined to do. As demonstrated, the
worst observed outcome is a valid tick's receipt degrading fail-safe to `could-not-classify`.

Before the next release audit round, or before /oss:curate promotes this: confirm whether GitHub
PR titles can carry newlines (their web UI is a single-line field and the REST/GraphQL title field
is documented as not permitting them, but this was not independently verified here). If confirmed
impossible, this fragment can be closed as reasoned-safe; if a newline can reach `.title`, open an
issue to harden `_CURATE`/`_TICK_ENDS` parsing against a forged same-column marker embedded in a
multi-line title, or to reject/escape a multi-line title before it reaches the receipt.
