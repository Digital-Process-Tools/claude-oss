Issue #1741's fix to `scripts/trap_curate.py`'s `sweep_resolved` made it re-derive the names it will
delete from the clone's own real, on-disk untracked set (`untracked_fragments(clone_dir)`) rather
than trusting `--copied` verbatim -- closing a path-traversal deletion hole. A self-review auditor
spawn (oss:auditor, on commit f9a77fa5) found a residual observability gap in the same fix: a
`--copied` name that is filtered out because it is not really present in the clone's untracked set
(a fabricated name, a transcription error, a traversal attempt that was correctly refused, or a
name that was already swept) is dropped with zero trace -- not counted in `removed`, not counted in
`failures`, nothing printed anywhere. The CLI's own report line,
`trap.d: removed {0} resolved stray fragment(s) from {1}`, and the `STRAY-NAMES:` line built from
`removed` therefore render identically whether nothing needed removing at all, or whether the pass
silently rejected a bogus/adversarial name -- exactly the defect class #1741 was fixed to guard
against, now happening one layer up in the reporting rather than in the deletion.

Ranked by the auditor as `misreports`, non-blocking (can ship behind this fragment) -- the fix a
reviewer would be sent to is the reporting/rendering logic (a distinct bucket that names a
`--copied` name refused for not being genuinely present, separate from `removed`/`failures`), not
the containment guard itself, which is correct and covered by both a positive and a negative test
(`test_sweep_resolved_removes_only_names_now_absent_from_the_worktree`,
`test_sweep_resolved_ignores_a_path_traversal_name`,
`test_sweep_resolved_ignores_a_copied_name_the_clone_never_actually_had`).

Left out of #1741's own diff deliberately: the issue explicitly asked not to expand scope beyond
the primary unchecked-deletion fix, and this is a reporting improvement, not a further deletion
hole. If promoted: `sweep_resolved` should return a fourth bucket (e.g. `refused` or
`not_really_present`) alongside `removed`/`failures`, and `main`'s CLI branch should print it
distinctly from `STRAY-NAMES:` so an operator (or a future adversarial-input audit) can tell a
quiet no-op from a quiet refusal.
