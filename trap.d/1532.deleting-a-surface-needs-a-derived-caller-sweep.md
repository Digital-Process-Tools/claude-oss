# Deleting a surface: derive the caller sweep, don't hand-pick it

Observed 2026-09-15 in the #1532 lane, which retired `lane_setup_claim.claim_and_register`
and about a dozen sibling names.

I did sweep for callers before deleting, and the sweep was good: one batched
`grep` over `scripts/`, `skills/`, `agents/` and `commands/` for every removed
name, plus a counted `grep` over `tests/`. It found 28 test files and I
migrated or deleted all of them.

CI still went red on both legs with

    tests/test_lane_prompt_1535.py:286
    E  AttributeError: module 'lane_setup_claim' has no attribute 'claim_and_register'

`tests/test_lane_prompt_1535.py` did not exist when I ran the sweep. It landed
on `main` with a sibling PR while my branch was in review, and my rebase had
nothing to conflict on because I had never touched that file. So the sweep was
correct and complete **about a tree that had moved underneath it**.

Two things follow, and the second is the one I had not internalised:

- **Re-run the caller sweep after any rebase onto a moved base**, not just
  before deleting. The names you removed are a fixed list; re-grepping it costs
  one call and is the only thing that sees a caller which arrived after your
  own work.
- **Choose the test set by derivation, never by hand.** My post-rebase run was
  a hand-picked list of "the lane's own tests plus the guards", which by
  construction could not contain a file I had never heard of. Deriving it
  instead --

      import pathlib
      mods = ("lane_setup", "lane_setup_claim", "select_issues", "doctor")
      [p for p in pathlib.Path("tests").glob("test_*.py")
         if any(("import %s" % m) in p.read_text() for m in mods)]

  -- returned 165 files and ran in 4 minutes (2,322 passed), against ~21
  minutes for the full suite. That is the middle option I did not consider:
  far broader than a hand-picked set, far cheaper than everything, and it is
  the one that would have caught this before CI did.

A related miss the same sweep surfaced: removing the `held_fetcher=` keyword
argument from six `select_issues` test files left six orphaned `def _held()`
helpers behind, plus a seventh of a different shape. Nothing failed -- an
unused nested function is silent -- so only a name-based grep found them.
**Deleting a parameter and deleting the fixture that fed it are two edits**,
and the second has no failing test to remind you.

Cost: one red CI round on two legs, and the report had to be reopened after it
was already validated.
