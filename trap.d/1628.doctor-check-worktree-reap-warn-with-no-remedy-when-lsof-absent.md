Gate-3 release audit (round 2, v0.37.1..HEAD) found: scripts/doctor_check_worktree_reap.py's could-not-tell arm (lines 115-121) reports WARN with no remedy. On any machine without lsof (Windows, and containers lacking it -- a case worktree_reap.py's own docstring at lines 34-38 already declares), every non-main worktree resolves could-not-tell, so this WARN fires on every /oss:doctor run on that machine and nothing there can ever clear it.

This is exactly the shape this repo's own doctor-check contract forbids: .claude/jit-context/paths/00-manual/doctor-check-contract.md states 'If nothing can clear it, the bug is in the check ... NOTICE is reserved for a check that has declared itself structurally unable to ever answer ... There is no state for a WARN that nothing can clear.' Two sibling modules in the same tree (doctor_check_event_filter.py, doctor_check_lane_coupling.py) already use NOTICE for exactly this shape.

Observed with a positive control: list_processes=lambda: None yields 'WARN worktree reap: could not be checked'; list_processes=lambda: [] on the same fixture yields 'OK worktree reap: no reapable worktrees' -- confirming the WARN is specifically the lsof-absent path, not a fixture artifact.

Fix shape: change the could-not-tell arm from WARN to NOTICE, matching the two sibling modules' own precedent for a structurally-unanswerable check.
