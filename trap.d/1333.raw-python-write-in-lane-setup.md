Early in this lane I patched tests/test_agent_report_schema.py with a raw `python3 - <<'PYEOF' ... open(path).write_text(...) ... PYEOF` heredoc instead of `supertool 'edit:@-'`. The PreToolUse hook fired the jit-context reminder (a-write-outside-supertool-meets-no-validator.md) AFTER the write had already gone through -- it is `mode: remind`, not a block, so the write landed with no jsonlint/gitleaks/rollback_on_fail coverage and no receipt. The edit happened to be correct (verified by git diff afterward), but nothing would have rolled it back if it had not been. Lesson: when composing a multi-anchor mutation programmatically (adding one dict entry plus one function definition to a Python test file), it is still faster and safer to do it as two `supertool 'edit:@-'` calls with literal old/new blocks than to write a throwaway Python patch script, even though the throwaway script feels more "surgical" for a two-site edit. The trigger regex for the reminder is `~open.*['\"][wa]['\"]|[.]write[(]|[.]write_text[(]` -- worth recognizing on sight before running anything that opens a path directly.

Also noted: `lane_setup.py`'s worktree-board output can misresolve the lane registry path when run before the worktree is created (it printed `no lane registry at .../1333-wt/.oss-lanes`, an odd "-wt" suffix that does not match this repo's actual worktree_root convention of `claude-oss-wt/<N>`). Did not chase the root cause since it did not block anything -- the guard list it printed was still correct and matched a subsequent, correctly-resolved call. Worth someone checking whether `--claim` runs before the worktree exists compute a different root than after.
