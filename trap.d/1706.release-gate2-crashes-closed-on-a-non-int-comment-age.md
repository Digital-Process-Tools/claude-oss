Gate-3 audit (v0.42.0 round 1, range v0.41.0..HEAD). `scripts/release_gate2.py`
(~line 178) compares `latest_review_comment_age_minutes` against the 30-minute
window with a bare `<`. #1706 fixed the top-level "field absent" shape, but a
value of the wrong TYPE for an otherwise-present field still crashes: feeding
`"5\n..."` (a string) raises `TypeError: '<' not supported between instances
of 'str' and 'int'`, which the script's own exit-1 (`EXIT_BLOCKED`) swallows --
so a malformed field renders exactly like "blocked", not like "could not
tell". What would settle it: type-check each field before the comparison and
return `could-not-tell` (exit 2) on a bad type, matching the shape #1706
already gave a missing key.
