Release audit (round 1, v0.27.1..HEAD) found: scripts/doctor_check_lane_other_label.py:76-110 calls
`gh label list --repo <slug> --json name --limit 200` and treats an empty/non-matching result as
`declared-and-absent`, which tells the maintainer to `gh label create` a label that may already
exist. If a repo has more than 200 labels and the declared `labels.lane_other` spelling sorts past
the 200-row cap, the check cannot see it and reports it missing anyway. The module already declares
a `could-not-tell` state for exactly this shape ("an unreadable forge is not evidence the label is
missing", lines 48-51 of the file) but never reaches it here -- it never checks whether `gh label
list` returned fewer rows than `--limit`, which is the one fact that would tell it whether it saw
the whole label set. This is the identical cap-read-as-absence class the same delta fixed for `gh pr
list`'s 500-row cap in scripts/doctor_check_stale_branches.py (#1253), where the chosen fix was a
server-side filter (`--search`) rather than a client-side unbounded `--limit`. Ranked `misreports`
(non-blocking) by the round-1 release audit.
