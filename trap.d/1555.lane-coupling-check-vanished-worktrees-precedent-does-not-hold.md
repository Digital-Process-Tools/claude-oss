Issue #1555 asks whether `scripts/doctor_check_lane_coupling.py` should be removed to match the
`check_vanished_worktrees` precedent in the same delta (both left #1530/#1532's `lane_patterns`
retirement behind them), or kept reporting `not-configured` pending `labels.lane_patterns` coming
back.

Checked both against `scripts/oss_config.py` and `scripts/scaffold.py`: `check_vanished_worktrees`
was removed because the local lane registry it read no longer has a write path anywhere in the
repo -- a structurally permanent `unknown` for every repo, forever. `doctor_check_lane_coupling.py`
is not in that state: `labels.lane_patterns` is not validated or rejected by `oss_config.py`, so a
repo (including this one) can still declare it in `.oss.json` and the check works exactly as
designed -- `lane_coupling.py`'s own `lane_coupling_report()` reads it and computes real ok/finding
answers. This repo's own `.oss.json` simply does not declare it any more, as a side effect of
issue #1530 retiring `select_issues.py`'s *different* consumer of the same key (adjacency for
dispatch bundling), not because lane-coupling-checking itself was ever decided against.

So the "identical situation two checks away" framing in #1555's own issue body does not fully
hold -- the two checks are not in the same state, only reading the same now-undeclared key for two
different purposes. Left `doctor_check_lane_coupling.py` in place rather than deleting working,
generic, already-tested machinery on that basis; its own `not-configured` NOTICE text is already
honest ("the ordinary state for a repo that has not adopted the lane-pattern convention, not a
finding") and not silently broken. Whether this repo should re-declare `labels.lane_patterns` (and
build real per-lane file-glob values for all five lanes) to restore coupling-checking here, or
whether the whole convention should be formally retired repo-wide, is a policy call on this
repository's own lane-coupling appetite -- not something a developer lane should decide by editing
`.oss.json` on the strength of stale documentation alone.
