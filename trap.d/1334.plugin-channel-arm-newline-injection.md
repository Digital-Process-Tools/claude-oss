Gate 3 release audit (round 1, dispatch gate3-d0e2cdbcc2ca, range v0.29.1..HEAD), class C, misreports,
non-blocking (considered as `forges` and rejected -- the only writer of the value is a plugin the
maintainer already installed, which already executes code in the session, so no privilege boundary
is crossed).

`bin/oss-workspace:1276-1320` with `scripts/doctor_check_mcp_channel_registration.py:536-551`.
`_plugin_channel_consumer_names` builds `plugin:{key}:{server_name}` where `server_name` is a raw
JSON object key out of an installed plugin's own `.mcp.json`, with no shape validation (:536-550).
`resolvable_plugin_server_name`'s own docstring names that value as "attacker-shapable data from a
plugin that need not be well-formed" and hardens it against an embedded `@` -- but the transport to
the shell was not hardened against a newline. The precheck prints `label` and `resolvable` as lines 1
and 2 (the `could-not-ask` arm strips newlines; the `single` arm does not), and the launcher reads
them with `sed -n '1p'` / `sed -n '2p'`.

Exercised, in-process, no files written:

```
resolvable_plugin_server_name('plugin:some@mkt:chan\nINJECTED')
  -> 'plugin:some:chan\nINJECTED'
sed -n '1p' -> plugin:some@mkt:chan
sed -n '2p' -> INJECTED          # the arm target, not the server name
```

`INJECTED` then becomes `plugin_channel_target`, is exported as `OSS_WORKSPACE_CHANNEL_ARM_TARGET`,
is printed verbatim into a doctor OK line, and reaches argv as `server:INJECTED` -- stays one quoted
argv element, so there is no word-splitting or option-parser reinterpretation. Combined with the
`single`-branch unverified-target finding, the practical effect is a session that opens without a
channel, or refuses to open, plus a doctor OK naming a server nobody configured.

Settles it: reject a label containing a control character in `plugin_channel_arm_decision`, or use a
length-prefixed / NUL-delimited transport.
