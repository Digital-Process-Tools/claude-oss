A lane that adds a file under agents/ has one more guard to run than the ones it
knows about, and the missing one turns every pytest leg red at once.

Observed on PR #1418 (2026-09-11): agents/scheduler-step.md was added with its budget
row in scripts/agent_budgets.py, its CLAUDE.md table row and layout line, and its
grant-is-total section. The lane ran test_agent_definition_budget_491.py,
test_claude_md_budget_table_709.py and test_agent_grant_is_total.py -- all green. CI
then failed all four pytest legs on tests/test_delegated_test_run_877.py:

    Bash-granted agent definition(s) ['scheduler-step.md'] are not in
    ALREADY_COVERED_ELSEWHERE, NO_TEST_CONCERN or REQUIRED_MARKER in this file

That guard makes every Bash-granted agent declare whether it may run the test suite,
and derives the expected set from agents/*.md itself -- so a new file is unaccounted the
moment it exists, and the guard refuses to guess which bucket it belongs in. Correct
behaviour. The lane just did not know the guard was there.

Cost: one CI round on four legs, one fix commit.

The set a lane adding agents/*.md has to run, as far as this instance establishes it:

    tests/test_agent_definition_budget_491.py
    tests/test_claude_md_budget_table_709.py
    tests/test_baseline_matches_disk_1014.py
    tests/test_agent_grant_is_total.py
    tests/test_delegated_test_run_877.py        <- the one that was missed

Possibly this belongs in the jit rule that already fires on agents/*.md
(loop-prose-parity.md), as one more line in its byte-budget bullet -- that rule is what
a lane editing an agent definition actually sees, and it names the budget guards but not
this one.
