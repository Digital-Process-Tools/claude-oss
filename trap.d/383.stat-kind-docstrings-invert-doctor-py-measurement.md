Gate 3 release audit (v0.37.0..HEAD, round 2) found: `scripts/oss_config.py`'s `_stat_kind`
docstring (around line 1766) and `ensure_worktree_root`'s new comment (around line 2932) both
assert, as the justification for the #383 fix, that `Path.is_file()`/`Path.is_dir()` "swallow
`OSError` internally", citing this repo's own 3.9/3.11/3.13 measurement. The cited authority says
the opposite: `scripts/doctor.py:1476-1479`'s `_safe_is_file` docstring states "`Path.is_file()`
catches `OSError` internally, but `EACCES`/`EPERM` is *not* in its ignored-errno set on at least
3.9, 3.11 and 3.13 ... only this repository's local 3.14 interpreter swallows it."

Observed directly (one command per installed interpreter, against a mode-000 parent): on 3.11 and
3.13, `exists()`, `is_file()` and `is_dir()` all raise `PermissionError`. 3.9, 3.10 and 3.12 are not
installed on the auditing machine, so those three are reasoned from `doctor.py`'s own prior
measurement, not independently observed.

Consequence: `ensure_worktree_root`'s new comment describes a pre-fix silent-absence bug ("both
fell through to `mkdir`") that, on the interpreters this repo actually runs in CI, was in fact a
loud raise rather than a silent swallow. The `_stat_kind` code itself is not wrong -- it is strictly
safer either way -- but the two docstrings/comments a future reader will consult to decide whether a
bare `.is_file()`/`.is_dir()` call elsewhere is safe currently say the opposite of what this repo's
own `doctor.py` already measured. (`trap.d/1584...md`, filed in the same audit round, is exactly
the kind of future call site this misdirects.)

Fix: correct both docstring/comment claims in `scripts/oss_config.py` to match `doctor.py`'s own
measured ignored-errno set, or re-run the probe across the full 3.9-3.12 CI matrix and update
`doctor.py`'s own claim if it turns out to be wrong instead.
