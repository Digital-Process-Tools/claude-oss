Auditor self-review finding on lane #1426/#1429/#1437 (PR fixing plugin_update.py's `--root` IndexError).

`_arg_value(argv, flag, default)` -- both the new one in `scripts/plugin_update.py` and the
pre-existing one in `scripts/statusline.py` (#1346), which it deliberately mirrors -- cannot
distinguish "the flag was never passed" from "the flag was passed but is the last argv token,
with nothing after it". Both cases silently return `default`.

A caller who types `--root` with nothing after it almost certainly meant to pass a value and
made a mistake; getting back `os.getcwd()` (or `None` for `--caller`) with no printed warning
is a misreport, not a crash -- the tool answers "root is cwd" for an invocation that was
actually malformed.

Confirmed by test: `plugin_update.main(["--root"])` (in `tests/test_plugin_update_debounce_753.py`,
added in this same lane to prove the fix does not raise IndexError) only asserts the value is
not `"--root"` -- it does not, and could not, assert that anything was reported about the
malformed flag, because nothing is.

This is a repeated design choice, not new invention: `statusline.py`'s own `_arg_value` (#1346)
already has this shape and nobody has filed it there either. Whether it is worth a `FAIL:`/stderr
line when a flag is present but valueless, in both `_arg_value` implementations, is a design
question (does an unqualified value-less flag scenario ever come up on a real invocation, or is
"forgot the value" rare enough that the crash-preventing fix is the whole of what matters) rather
than something to decide mid-lane.

Ranking table row: misreports, non-blocking.
