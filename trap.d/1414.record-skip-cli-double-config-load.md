`scripts/next_action.py`'s `_record_skip_cli`/`_take_cli` (#1414) call `rank(root)` once to confirm
the payload is `RANKED` -- which internally succeeds only when `oss_config.load` returned a real
config -- then call `oss_config.load(Path(root) / ".oss.json")` a second, independent time to read
`state_file`. If that second read fails (the file removed or corrupted in the narrow window between
the two reads, or a future refactor that makes the two loads diverge for a non-race reason), the
code folds into the same "no state_file configured" message a genuinely unconfigured repo produces
-- a caller cannot tell "you never set state_file" from "the config could not be re-read a moment
later."

Observed by the self-review oss:auditor spawn on the #1414 diff (HEAD 6830151e). Ranked
`misreports`, non-blocking (reasoned, not observed -- would need to race the filesystem to
trigger), and the honest fix is a real refactor: have `rank()` expose the config it already loaded
internally (or a shared `_load_and_validate` helper both `rank()` and the CLI functions call once),
rather than the two independent loads today. Left as a follow-up rather than done in this lane,
since it touches `rank()`'s own return shape and is a bigger change than its severity warrants
right now.
