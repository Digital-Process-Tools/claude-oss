The `supertool-payload-forms` jit rule cannot prevent the round trip it describes, because it
fires on the same call that fails.

Observed 2026-09-05, in this repository's own scheduler session, filing what became #1075. The
markdown body was drafted in the scratchpad and handed to `gh-issue-create:@FILE`. The
`PreToolUse` hook injected `supertool-payload-forms.md` — the rule that says exactly this will
fail — and the call failed in the same turn:

    ERROR: failed to parse payload: Expected '=' after a key in a key/value pair
    (at line 1, column 7) (expected JSON or TOML with title/body)

That is the rule working as designed and still costing the full round trip. `PreToolUse` fires
after the command has been composed, so the earliest moment the rule can reach a reader is the
moment the wrong command is already written. The rule's own text says the error "costs one round
trip — **each time**, and it has been paid at least twice"; this is the third payment, and the
second one inside a week, by a reader who had the rule's text in context.

What the rule cannot do is not a defect in the rule's wording — the wording is clear and the
conversion snippet in it works verbatim. The gap is structural: a `mode: remind` rule matched on
`~gh-issue-create` is read at composition time only if something else caused the reader to think
about `gh-issue-create` before writing the file, and the natural order is to write the body first.

Two shapes worth weighing, neither of them tried:

- Match the rule one step earlier, on whatever op writes the draft (`paste:`/`Write` into a
  scratchpad `.md`), so it arrives while the body is being written rather than when it is being
  submitted. This trades a precise match for an early one and would fire on many drafts that are
  never destined for an issue.
- Make the tool accept it. `gh-issue-create:@FILE.md` could read a markdown file as
  `title = first line, body = rest` — which is exactly the conversion the rule tells every reader
  to perform by hand, and would move the fix upstream into supertool where it stops being a thing
  anyone has to remember. That is a supertool change, not a claude-oss one.

Cost this time: one failed call plus one conversion, maybe ninety seconds. The reason it is worth
logging anyway is the tally — a rule whose own text records the cost being paid repeatedly by
people who have read it is evidence about rule placement, not about the readers.
