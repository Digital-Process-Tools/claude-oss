Gate 3 round 1, v0.42.1..HEAD (#1745, from PR #1754): the fix pins recon's reads to the named
worktree by telling it to "`cd` into the named path before your first read"
(`agents/recon.md:50`). This harness resets the working directory between Bash calls -- a call
that ran `cd .../claude-oss/scripts && pwd` printed `.../scripts`, and the very next call's
plain `pwd` printed `.../claude-oss` again, confirmed directly in the gate-3 audit session.

So the pin only covers the first call. Every later read in the same recon spawn goes back to
the ambient cwd, which is exactly the #1745 failure this fix set out to close: a dirty sibling
checkout can still flip a verdict to a false `already-shipped`. Nothing in `agents/recon.md`
names the `cwd:PATH` supertool prefix, which is what would actually pin each call.

Ranked `misreports` (recon reports a verdict about the wrong tree) -- non-blocking. What
settles it: whether a spawned `oss:recon` keeps its directory between Bash calls; this
session's own is observed not to.
