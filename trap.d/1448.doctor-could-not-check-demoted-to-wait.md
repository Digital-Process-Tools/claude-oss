Release audit (gate 3, round 2, v0.33.1 candidate, dispatch token gate3-r2-c044551201dee01c) found:
scripts/doctor_check_auto_update.py:270-281 (added by e08c311, #1448/#1440) answers only whether
`installed_plugins.json` is readable right now, but `_report_plugin` uses that single fact to demote
*every* `could-not-check` receipt to `WAIT ... settles on the next SessionStart check`.

Three of the four `could-not-check` arms in scripts/plugin_update.py never had an unreadable
install record at all: marketplace refresh failed (offline, `claude` not on PATH, a broken
marketplace -- that arm itself reads `installed_version` successfully), every `claude plugin
update` call failing, and an undeterminable opt-out. On those, a readable record is the *steady*
state -- nothing is going to settle on the next SessionStart -- and a standing, actionable WARN now
prints as WAIT, which doctor.py's verdict arithmetic does not count. The run reads `VERDICT: ok`
and statusline's `dr` marker follows. This is the shape the same commit's own prose names as the
thing not to do ("a WARN wearing a self-heal disclaimer").

Reasoned, not observed: tests/test_auto_update_receipt_484.py's three #1440 tests all use
`detail: "the install record could not be read"`; none feeds the marketplace-failed or
update-failed detail through this path.

Ranked `misreports`, non-blocking (findings.md's table) -- did not stop the v0.33.1 tag.
