Self-review on #1788 (`_default_plugins_root()` in `scripts/plugin_update.py`) found the same
defect class -- a hardcoded `~/.claude/plugins` default that never consults `$CLAUDE_CONFIG_DIR` --
duplicated in at least four other, unfixed sites, all confirmed by reading the tree at commit
dc7b67a8 in this repo:

- `scripts/statusline.py:1703-1704`, `plugins_root_default()` -- a standalone second copy of the
  same default. Feeds `installed_plugins()` (statusline.py:1770), `installed_plugins_registry_
  readable()` (statusline.py:1822), and a third call site at statusline.py:2939.
  `installed_plugins()` in turn is consumed by `scripts/doctor_check_latest_skew.py` (the
  plugin-currency doctor check) and by statusline's own plugin-facts rendering -- so a machine
  with `$CLAUDE_CONFIG_DIR` set gets the same false not-installed/not-current reading in both
  `/oss:doctor` output and the status line.
- `bin/oss-workspace:1231` and `bin/oss-workspace:1477` -- both
  `registry = os.path.expanduser("~/.claude/plugins/installed_plugins.json")`, in the ASK_CONSUMER
  and FIND_CONSUMER blocks that run at session launch, before `plugin_update.py` is ever reached.
- `scripts/doctor.py:4468` -- the identical literal, resolving supertool's install path for a
  doctor check.
- Not independently confirmed (grep-matched only, flagged for a follow-up read before acting):
  `scripts/doctor.py:6176`/`6227`/`6362` and `scripts/doctor_check_mcp_channel_registration.py:432`
  also contain the literal `~/.claude/plugins` / `~/.claude/plugins/installed_plugins.json` text --
  worth checking whether these are live code paths before folding them into the same fix.

Issue #1788's own trap.d predecessor (`trap.d/1768.plugin-update-enablement-conflates-config-dir-miss-
with-not-installed.md`) already named the whole repo, not one file, as the blind spot; #1788's
fix closed it for `scripts/plugin_update.py` alone. `_default_plugins_root()` is the shape the
remaining sites should converge on, but it lives in `plugin_update.py`, which `bin/oss-workspace`
and `statusline.py` do not import today (a shared import would need to land somewhere both can
reach without introducing a new cross-import), so this is a real design question, not a
one-line follow-up, and reaches well outside this lane's own file set (scripts/plugin_update.py,
tests/test_workspace_plugin_enabled_1768.py). Not blocking a release; logged here rather than
fixed inline.
