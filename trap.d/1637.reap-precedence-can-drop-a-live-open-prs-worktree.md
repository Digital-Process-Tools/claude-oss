Gate-3 audit (v0.42.0 round 1, range v0.41.0..HEAD). `scripts/worktree_reap.py`'s
`branch_merge_state` (lines ~265-283) walks a branch's PR rows and lets the last
row win unless a MERGED row appears (#1637), and #1693/#1698 later gave CLOSED
its own reapable meaning. `gh pr list` returns newest-first, so a branch whose
OLDER PR was closed and whose NEWER PR is still open reads `closed` overall --
confirmed with a fake `run` fixture: `[OPEN #2, CLOSED #1]` returns `('closed',
...)`, the reverse row order returns `not-merged`. `plan_reap` then marks the
tree reapable and runs `git worktree remove --force` plus `git branch -D`.
Nothing pushed is lost, but a live, idle lane's worktree is destroyed while its
PR is still open. The same precedence, plus "MERGED wins forever", can also
reap a reused `doctor/<check-slug>` branch (#1703) while its new PR is open --
reasoned, not observed. Existing tests only cover single-row fixtures
(`tests/test_worktree_reap_1628.py:252,346`). What would settle it: a mixed
OPEN+CLOSED fixture asserting `not-merged`, and a rule that an OPEN row always
wins regardless of position.
