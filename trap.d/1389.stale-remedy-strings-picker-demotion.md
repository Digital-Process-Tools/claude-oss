Self-review of #1389's picker-demotion diff (both the Explore reviewer and the oss:auditor spawn,
independently) found the same class of defect, larger than either one stated alone: this diff moves
setup.md, scaffold.md, triage.md, curate.md, changelog.md and install-audit.md out of the top-level
picker, so a bare /oss:setup, /oss:scaffold, /oss:triage or /oss:curate no longer resolves as a real
slash command -- only /oss:run setup (and so on) or a direct file read reaches them now. Several
already-live runtime remedy strings across the codebase still print the bare, now-dead form as the
literal fix-it instruction:

- scripts/oss_config.py: multiple return sites print "Run /oss:setup to write it." (lines around
  1796, 1823, 1833, 1841, 2041, 2806) and "re-run /oss:setup once the label exists." (around 3658).
- scripts/doctor.py: "Run /oss:setup." / "or re-run /oss:setup." (around 8377, 8383, 8921) and
  several "Run /oss:scaffold." remedies (around 5576, 5684, 5721, 5749, 5758, 5801).
- scripts/oss_rules.py:172,191 -- this one is more than a remedy string, it is the literal text
  oss_rules.install() WRITES INTO EVERY MANAGED REPO'S OWN rule layer ("/oss:scaffold vendors the
  checker; run it and this rule is rewritten"), so this is live, shipped, per-repo content, not just
  this plugin's own prose. commands/run/scaffold.md:353-354 quotes this generator's exact output in
  a table describing it, so that quoted table is accurate to what the generator currently does and
  should NOT be fixed independently of scripts/oss_rules.py -- fixing one without the other would
  make the doc lie about the generator instead of the generator lying about the picker.
- scripts/trap_curate.py, scripts/workspace_routes.py (the TRIAGE/CURATE remedy dict), 
  scripts/select_issues.py, scripts/statusline.py, scripts/scaffold.py: similar literal /oss:triage,

- commands/doctor.md:45 ("the fix is /oss:setup. Offer it...") and commands/tick.md:297 ("Stop and
  say so. /oss:setup writes it.") -- both files I deliberately did NOT touch in this lane (see the

I fixed the instances that were (a) plain, standalone invocation text, not a generator's quoted
output, and (b) inside a file already part of this diff's touched set: commands/run/setup.md (fixed
earlier, in the original commit), commands/run/install-audit.md:60, commands/run/triage.md:8. I did
NOT fix docs/status-line.md:3 ("/oss:scaffold writes .oss/statusline.py"), commands/doctor.md:45,

updated in a way that stays correct for a repo that has not yet re-scaffolded (an already-written

Ranked misreports (a receipt/remedy naming a next step that is not actually correct any more) --
per findings.md's table, non-blocking, ships behind this trap.d fragment rather than filed as an
issue. Whoever curates this: the fix is a project-wide sweep for the literal substrings
"/oss:setup", "/oss:scaffold", "/oss:triage", "/oss:curate", "/oss:changelog", "/oss:install-audit"
across scripts/*.py and the still-top-level commands/{tick,doctor,release}.md, replacing each
