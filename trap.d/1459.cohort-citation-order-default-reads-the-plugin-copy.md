# `cohort_citation_order.py` without `--claude-md` checks the installed plugin's CLAUDE.md, not the checkout being released

Observed cutting v0.33.0 (2026-09-11). `commands/release.md`'s marker gate quotes the call as
`cohort_citation_order.py --state <state file> --at <now>` -- no `--claude-md`. Run exactly that
way from the release checkout, with the marker already rewritten to cite `cohort-29`, it printed
`ok -- cohort-28 was already frozen` and exited 0.

`--claude-md` defaults to "this repo's own", which resolves relative to the script's location --
`${CLAUDE_PLUGIN_ROOT}/CLAUDE.md`, the 0.32.0 install's copy still naming the previous release's
cohort -- not to the cwd. So the check read a file the release does not touch and reported `ok`
about it. Same class as the top of CLAUDE.md: a check that never looked at the thing under
question, rendering identically to one that did.

Caught only because the printed cohort number did not match the paragraph just written. With
`--claude-md ./CLAUDE.md` it read the right file: `ok -- cohort-29 was already frozen`.

Cost: one call. The fix is one of two: `commands/release.md` adds `--claude-md ./CLAUDE.md` to the
quoted call, or the script defaults to the cwd's `CLAUDE.md` when the repo being checked is
evidently not the plugin's own -- the latter is the same "this repo is the plugin's source" trap
`checklist_skew.py` already names.
