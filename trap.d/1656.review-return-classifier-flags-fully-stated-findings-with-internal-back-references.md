Self-review round for issue #1656: an oss:auditor spawn's final message opened with
`FINDINGS: 3` and fully restated each of the three findings in standalone paragraphs -- nothing
was left unstated or deferred to "see above" for its substantive content. But two of the three
findings, once fully stated, also included a short internal cross-reference back to an earlier
paragraph in the same message ("Same evidence and same ranking row as the Class A finding above
(they are one defect viewed two ways); not counted twice.") and a closing tally line ("Findings: 3
(one A/B-paired defect counted once, one test-coverage regression, one arithmetic
misstatement...)").

Piped through `scripts/review_return.py --framed -`, this classified as `referred-not-stated`
(exit 3), not `states-findings` -- the tool's own reasoning: "the header claims 3 finding(s) and 16
enumerable block(s) trail it, but the message also points at material it does not carry -- a
marker count cannot tell a stated finding from a list of file names, so the back-reference
decides." The word "above" and a summarising tally at the end were both read as pointers to
material outside the message, even though the pointed-to material was, in fact, inside the same
message, fully stated moments earlier.

This cost one full re-spawn (the one permitted retry agents/developer/review-return.md allows) to
get a clean `states-findings` classification, by explicitly instructing the second spawn never to
use the word "above" and never to write a closing tally, and to merge any genuinely-duplicate
observation into one single restated finding rather than cross-referencing it. The retry's content
was NOT better or more complete than the first spawn's -- it was the same information, reformatted
to avoid tripping the classifier's own back-reference heuristic.

Worth a jit-context note (not written here, since deciding that is /oss:curate's job): a review
brief that asks for `FINDINGS: <n>` should also say, up front, "do not use the word 'above' or any
other cross-reference, even when the referenced material is also fully stated in this same
message; merge duplicates into one finding instead" -- this would have avoided the wasted retry
entirely, since the content itself was fine and only the classifier-tripping phrasing needed to
change.
