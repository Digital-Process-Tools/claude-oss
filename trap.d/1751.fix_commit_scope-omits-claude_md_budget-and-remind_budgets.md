`skill_phases.DOCUMENTS` -- confirmed by reading the module directly (its own docstring
even names these four explicitly). It does not read `claude_md_budget.BUDGETS` or
`remind_budgets.BUDGETS`.

`CLAUDE.md` and `scripts/claude_md_budget.py` (correcting a stale byte count and an
off-by-one paragraph cross-reference inside CLAUDE.md's own self-referential bookkeeping
section) was scored `within-scope -- touches 2 file(s), none byte-budgeted` by
`fix_commit_scope.py --repo . --base 486b4b5c --head c45e0f45`, even though CLAUDE.md is
exactly the file `claude_md_budget.py`'s own module docstring says this repo "already
governs with its own ceiling" -- it is simply governed by a fifth module the check never
reads.

precisely where three real errors were found and fixed across this same review chain (a
stale intermediate byte count, and two separate off-by-one paragraph cross-references) --
exactly the "a sentence that parsed two ways" failure mode `fix_commit_scope.py`'s own
docstring cites (PR #921) as the reason this check exists at all. A future fix that
touches only CLAUDE.md and its own budget script would not be flagged for a mandatory
second pass, even though it sits in the highest-risk file for this exact defect class.

Not fixed here: out of scope for #1745/#1751, and deciding whether `claude_md_budget.py`
and `remind_budgets.py` belong in `fix_commit_scope.py`'s own budgeted-file list is a
small, separate, easily-reviewable change rather than something to fold into an unrelated
diff.
