`scripts/doctor.py`'s `_malformed_repo` (around lines 8781-8786) carries a comment attached to
its per-segment `?`/`#` check that reads, in effect, "neither `oss_config.repo_problem` nor the
inline fallback above excludes them [`?`/`#`]." That was true before #1475. After #1475 widened
`oss_config.REPO_RE`'s excluded character class to also exclude `?` and `#`, the claim is false
on `doctor.py`'s primary path: when `oss_config is not None`, `oss_config.repo_problem(repo)` a
few lines above (line 8771) now already rejects a slug containing `?` or `#`, so `_malformed_repo`
returns `True` before ever reaching the per-segment loop the stale comment describes -- the exact
same redundancy `#1475` documented and fixed in `statusline.py`'s analogous
`_REPO_QUERY_FRAGMENT_RE`/`_REPO_RE` docstring pair. The comment is still accurate for the
`oss_config is None` fallback branch (that inline fallback re-implements the pre-#1475 character
class and was correctly left unchanged), just not for the primary path it also currently describes
unconditionally.

Confirmed live: `python3 -c "import sys; sys.path.insert(0,'scripts'); import oss_config;
print(oss_config.repo_problem('o/n?x'))"` from the post-#1475 tree prints a non-None problem
string, contradicting the comment's blanket claim.

Not fixed in #1475's own lane: `scripts/doctor.py` was owned by a concurrent peer lane
(`doctor*.py`, `bin/oss-workspace`) for that tick, so #1475 could not touch it without risking a
merge collision. Severity low -- comment-only, no behavior change, `doctor.py`'s own tests
(`tests/test_doctor_slug_guard_1055.py::test_malformed_repo_rejects_query_and_fragment_characters`)
still pass since both layers now agree on the answer.

Suggested fix, for whoever next touches `scripts/doctor.py`: reword the comment above the
`if "?" in segment or "#" in segment:` check to say it is now a redundant second line of defense
on the `oss_config is not None` path (mirroring `statusline.py`'s own corrected
`_REPO_QUERY_FRAGMENT_RE` docstring), and still load-bearing on the `oss_config is None` fallback
path.
