Issue #1566 fixed the reported instance -- `release_trigger.py`'s
`merged_prs_condition` measuring its range from a local `HEAD` that a tick's own clone
never re-pulls after a squash merge lands on the forge -- by fetching the tracked
remote and reporting `could-not-evaluate` when HEAD is still behind afterwards.

The self-review (`Explore` reviewer) found the same shape is still fully live in every
other direct caller of `scripts/release_delta.compute()`, none of which got the same
staleness guard:

- `agents/release-auditor.md` and `commands/release.md`'s gate 3 invocation
  (`python3 .../scripts/release_delta.py --repo . --json`), which decides the actual
  audited/tagged range -- arguably a higher-stakes instance than the trigger heuristic
  this issue fixed, though the releaser's own worktree is freshly cut from a fetched
  `origin/<default_branch>` each time, which is a real mitigant the scheduler's
  long-lived clone does not have.
- `scripts/release_version.py`'s `_baseline()` (`release_delta.compute(repo, None,
  config_path)`), used to pick the tag to propose the next version from.
- `scripts/triage_trigger.py`'s own `compute()`, which has the identical
  `delta if delta is not None else release_delta.compute(repo)` pattern for its
  `triage_after_release` condition.

Worth deciding: does the fix belong in `release_delta.compute()` itself (root cause,
benefits all four consumers with one change) rather than repeated per-caller the way
issue #1566 did it once? And is the releaser's fresh-worktree mitigant strong enough
that its own call site can stay as-is while `release_version.py` and
`triage_trigger.py` (which have no such guarantee about when/where they run) get the
same treatment issue #1566 gave `release_trigger.py`?

Not fixed here: extending the guard to four more call sites (one of them,
`release_delta.py` itself, is shared infrastructure with its own test suite) is well
past issue #1566's own blast radius, and the releaser's fresh-checkout mitigant means
this is not obviously a release blocker today.
