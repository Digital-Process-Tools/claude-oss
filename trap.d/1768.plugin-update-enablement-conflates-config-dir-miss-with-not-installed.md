Gate 3 round 1, v0.42.1..HEAD (#1768/#1769 territory): `scripts/plugin_update.py`'s
`enablement()` only reads `~/.claude/plugins/installed_plugins.json`. `bin/oss-workspace`'s
new `not-installed` branch (#1768) treats a missing file the same as a registry that was read
and found no match in -- but `git grep CLAUDE_CONFIG_DIR -- scripts bin` finds nothing anywhere
in this repo, so a machine that keeps its Claude config elsewhere (`$CLAUDE_CONFIG_DIR` set)
gets a hard refusal (exit 1) from the launcher for a plugin that is actually installed, plus an
offer to run `claude plugin install ... --scope project` where Enter means yes -- which would
write the repo's own `.claude/settings.json` for a plugin already present.

Ranked `misdirects` (a refusal names a next step the caller never asked for) -- non-blocking.
Before this delta the same blind spot only degraded status output; this delta turns it into a
hard refusal.

What settles it: whether Claude Code writes `installed_plugins.json` under
`$CLAUDE_CONFIG_DIR/plugins` when that variable is set. If so, a missing file at the default
path should read "could not tell", not "not installed".
