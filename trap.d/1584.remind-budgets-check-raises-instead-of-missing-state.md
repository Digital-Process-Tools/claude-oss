Gate 3 release audit (v0.37.0..HEAD, round 2) found: `scripts/remind_budgets.py`'s `check()`
documents a deliberate third state ("missing") for a budgeted jit-context body that is genuinely
absent, distinct from `ok`/`over` -- its own docstring argues this matters because answering `ok`
for an absence "is exactly the absence-read-as-clean defect this repo is named after". But the
branch that produces it is a bare `if not path.exists():`, and `Path.exists()` does not swallow
`EACCES`/`EPERM` on the interpreters this repo actually runs (3.9/3.11/3.13, per `doctor.py`'s own
`_safe_is_file` docstring and measurement) -- only local 3.14 swallows it.

Observed on a mode-000 parent directory: `check()` raises `PermissionError: [Errno 13] Permission
denied` rather than returning any of its three documented states. So a present-but-unreadable
budgeted file produces neither `ok`, `over`, nor `missing` -- it produces an uncaught exception from
a checker whose contract is "a list of dicts". `tests/test_remind_budgets_1584.py`'s
`test_check_reports_missing_rather_than_silently_passing` only covers a genuinely absent path, so
this input has no positive control.

Same shape exists at `agent_budgets.py:615` and `claude_md_budget.py:136` already (pre-existing,
not new in this delta) -- `remind_budgets.py` is a new instance of an existing class, not a
regression.

Fix candidates: wrap the `exists()`/read call in a `try/except OSError` and report a fourth state
(e.g. `unreadable`) the same way `doctor.py`'s own `_safe_is_file` already does, or explicitly
narrow the docstring's claim to interpreters that actually swallow the error.
