# _WORKTREE_RE assumes a forward-slash worktree path separator

`scripts/loop_cost_report.py`'s `_WORKTREE_RE = re.compile(r"-wt/(\d+)\b")` -- the rule 2 fallback
that attributes an `oss:auditor` transcript's spend to an issue via its worktree path
(`attribute_issues` in the #1618 `--per-issue` mode) -- only matches a forward-slash-separated path.
`scripts/lane_setup_worktree.py`'s `derive_worktree()` builds that path with `oss_config.resolve_
worktree(...)` and reports it as `str(path)`, a `pathlib.Path` stringified with the host's native
separator. On Windows that renders with a backslash, so `_WORKTREE_RE` never matches and a real
Windows-run `oss:auditor` transcript falls through to `RULE_UNATTRIBUTED` even though its prompt
names the worktree path plainly -- not a dropped record (the `unattributed` bucket is explicit and
the reconciliation total still holds), but every Windows-run auditor lane's spend silently
misreports as unattributed rather than under its issue.

Found by `oss:auditor` in #1618's own self-review round, ranked `misreports`/non-blocking (can ship
behind this fragment per `findings.md`'s ranking table) rather than fixed inline. Reasoned, not
observed -- no Windows machine was available to confirm the regex actually fails against a real
backslash path; confirmed only against the regex literal and `derive_worktree`'s own `str(path)`
call. `_BRANCH_RE` (the branch-name fallback beside it) is not the same risk: git branch names are
always forward-slash-separated regardless of host OS.

The existing test, `test_worktree_path_attributes_the_auditor` in
`tests/test_loop_cost_report_1618.py`, hardcodes a POSIX-separated worktree path ending in
`claude-oss-wt/1583` -- no test in that file constructs a backslash-separated path,
so CI's own Windows leg (which does run, per `.github/workflows/tests.yml`) cannot expose this,
since the test string itself is not OS-dependent.

Possible fix: match on the path's final segment split by either separator (`re.split(r"[\\/]",
text)`), or normalize with `PurePath`/`os.path.basename` before matching, rather than assuming
`/`.
