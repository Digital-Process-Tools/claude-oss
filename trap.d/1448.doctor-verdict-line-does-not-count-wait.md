Release audit (gate 3, round 2, v0.33.1 candidate, dispatch token gate3-r2-c044551201dee01c) found:
scripts/doctor.py's VERDICT line (and the install-audit equivalent) appends ", N notice(s)" so a
tail-only reader sees that non-gating findings exist -- but a WAIT is neither gated nor counted the
way NOTICE is, so a run whose only findings are WAIT lines prints a bare `VERDICT: ok`,
indistinguishable from a run with nothing at all. The individual WAIT lines still print (and
`--findings` keeps them), so this is the weakest of the round's findings -- only the one-line
summary is affected, not the full report.

Ranked `misreports`, non-blocking (findings.md's table) -- did not stop the v0.33.1 tag.

Settling fact: a maintainer call, not a mechanical one -- whether WAIT should be counted in the
VERDICT text the way NOTICE is (per #764's reasoning for NOTICE). If the answer is no, this is a
documented choice and the fragment can be declined outright at /oss:curate.
