The trap.d emptiness carve-out makes a drained directory and a broken scan render identically.

Found by an oss:auditor pass over PR #1331 (chore/curate-trap-d-1319, merged as 30e2489), the curate
that drained 50 trap.d fragments into 7 rules, 6 merges and 7 issues. Non-blocking, ranked
`misreports`, so it is logged here rather than filed.

`tests/test_content_invariants.py` replaced `test_trap_d_has_documents` with
`test_trap_d_is_present_and_readable`, and added a `DRAINABLE_MID_LANE_DIRS` carve-out to
`test_every_shipped_mid_lane_dir_has_documents`. The `missing` list now excludes trap.d and
changelog.d whenever `(REPO_ROOT / dirname).is_dir()` is true -- regardless of why the glob scan
returned zero documents. `_shipped_mid_lane_documents` drives that scan from
`SHIPPED_MID_LANE_DIRS = [("trap.d", "*.md", False), ...]`.

So a caller sees the same clean "nothing missing" result in two cases that mean opposite things:
trap.d is legitimately empty because a curate just drained it (the change's own intent), or the glob
pattern is broken and will report zero for that directory from now on, forever, silently.

The carve-out itself is right -- the old test would have failed on every post-curate tree, and that
is exactly the false alarm the change set out to remove. What is missing is the third state. The new
positive control, `test_an_empty_drainable_dir_is_not_reported_as_missing`, only exercises
`Path.is_dir()` and `Path.iterdir()` against a bare `tmp_path`: it proves stdlib behaviour, not that
the guard can still catch a broken scan for trap.d specifically. It never calls
`_shipped_mid_lane_documents` or the `missing` computation at all.

What would settle it: a fixture where `_shipped_mid_lane_documents` (or the glob under it) is
patched to return zero for trap.d while the directory is genuinely non-empty on disk, asserting the
guard still fails. That is the negative-assertion-needs-a-positive-control rule from CLAUDE.md,
applied to the guard rather than to the code it guards.

Worth noting where this landed: the change is in the file whose whole job is policing this
repository's own defect class, and it introduced an instance of it. Nobody was careless -- the
carve-out is a correct fix for a real false alarm, and the missing state is only visible if you ask
what the check prints when it cannot look.

for nine hours. This audit was the only review it received, dispatched by a different session after
its own release gate 2 refused to tag while it stayed open. See trap.d/1333.multiple-schedulers-one-clone.md.
