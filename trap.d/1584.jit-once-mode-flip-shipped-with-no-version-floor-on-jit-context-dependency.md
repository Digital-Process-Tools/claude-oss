Gate-3 release audit (round 1, v0.37.1..HEAD) found: .claude-plugin/plugin.json:19-23 declares dependencies: [supertool, remember, claude-jit-context] as bare strings with no version constraint. Commit 09155e9a (#1584 part one) flipped 19 rules from mode: remind to mode: once, and changelog.d/1584.fixed.once-mode.md:2-3 states this dedup is correct only on claude-jit-context >= 0.10.0, where once dedupes per reader (transcript_path).

On an older install, once dedupes per session, and a spawned agent inherits its parent's session id -- so all 19 rules would be delivered to whichever agent trips them first in a session and to no later spawn in the same session, silently. A rule not delivered renders exactly like a rule delivered and obeyed -- this repo's own defect class.

Blast radius is bounded: mode census over the corpus confirmed the 3 mode: block rules were not touched by the flip -- enforcement guards are unaffected; only advisory (remind-turned-once) delivery degrades on a stale jit-context install.

Precedent for naming this class of gap already exists in this repo: doctor_check_supertool_validators.py:32,173 reports "plugin declares no minimum version for supertool" as a known limitation. The same is now true of claude-jit-context, with a new consequence attached (delivery silently narrows to one spawn per session on an old install, rather than merely a validator feature going unused).

Related and already known, not re-filed here: CLAUDE.md:515-516 still asserts per-session dedup as current fact and the delta did not touch that passage; trap.d/1584.jit-rules-and-subagents-vocab-stale-after-once-flip.md (already in this same delta) records the same staleness for the vocabulary file.

Fix shape: either declare a minimum claude-jit-context version in plugin.json, or have doctor.py/plugin_update.py check the installed jit-context version and report a finding (not silently degrade) when it is below 0.10.0 and the corpus contains once-mode rules.
