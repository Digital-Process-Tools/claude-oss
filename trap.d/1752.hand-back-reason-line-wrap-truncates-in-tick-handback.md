Gate-3 release audit for v0.43.0 (round 2, over v0.42.0..HEAD, commit 2041b224 / #1744) found a
second, non-blocking finding (F2, class A / misreports) while looking at the same #1740 fix that
produced F1 (filed as #1752):

`agents/sub-manager.md`'s new hand-back template for the role-write-refused case wraps its `REASON:`
line across two lines. `scripts/tick_handback.py` keeps only the first line of a multi-line REASON,
so the scheduler's recorded reason ends up as the shorter "could not declare" rather than the fuller
"sub-manager; refusing to proceed un-declared" the template intends. The load-bearing part -- the
write-exit and force-write-exit codes -- survives, so the cost is a slightly truncated reason string,
not a wrong classification.

Confirmed by piping the template's own filled-in text (with the wrapped REASON) through
`python3 scripts/tick_handback.py -`: it correctly classified as `could-not-run`, but the printed
reason dropped the second line.

What would settle it either way: whether the template should be rewritten to keep REASON on one
line, or whether `tick_handback.py` should be taught to join continuation lines before parsing.

Not ranked as blocking -- per findings.md's ranking table, a `misreports` row can ship behind a
trap.d fragment, which is this one.
