Release audit (v0.38.0..HEAD, round 2) found: `scripts/doctor_check_triage_route.py:170-172`
(#1651's new doctor check) decides the triage route is "configured" with
`config.get(TRIAGE_ROUTE_THRESHOLD_KEY) is not None`. The reader that actually arms the
route, `scripts/workspace_routes.py`, disagrees:

    def _valid_threshold(value):
        return isinstance(value, int) and not isinstance(value, bool) and value >= 0

`decide()` sends any other value (a string, a bool, a negative int, a float) to
`COULD_NOT_COUNT`, which can never resolve to `OVER` -- so a `triage_route_threshold` set
to e.g. `"10"` makes the route permanently dead while `doctor_check_triage_route.py` reports
NOTICE "not a fault and nothing is blocked", the opposite of what #1651 added this check to
warn about.

The `is not None` shape is inherited from `scripts/doctor_check_trap_queue.py:65-66` (#1610,
outside this delta) for the sibling `curate_route_threshold` key -- same gap, so the fix
probably belongs in both checks: validate with the same predicate the reader uses
(`workspace_routes._valid_threshold` or equivalent), not a bare `is not None`.

Not reachable in this repository today: `.oss.json` sets no `triage_route_threshold` at
all, so the correct WARN arm is the one actually taken here.
