Release audit (v0.38.0..HEAD, round 2) found: `scripts/doctor_check_claude_md_size.py:129-138`'s
`valid_threshold` requires `isinstance(threshold, int)`, so a JSON value like
`"claude_md_size_threshold": 59000.0` (a float, not the int the code wants, but a value
that IS present and configured) falls through to the `unconfigured` arm, whose NOTICE tells
the maintainer "no claude_md_size_threshold configured in .oss.json to compare it against".

That sentence is false in this case: a value IS configured, and the check silently
declined it rather than saying so. "Never set" and "set in a shape this check rejects"
print identically. The docstring already names the int-only choice, but the rendered NOTICE
line does not carry that distinction through to the caller.

Remedy: either accept a float that is integral (e.g. `59000.0 == 59000`), or -- if the
int-only restriction is deliberate -- render a different, explicit message ("configured but
not an integer, ignoring it") instead of folding it into the same NOTICE as "never
configured".
