# A `find`-first section locator repoints silently when the heading text appears earlier in prose

**Observed:** `tests/test_claude_md_currency.py` and `tests/test_claude_md_reach_probe_scope_711.py`
both locate their section with `text.find("## What is not proven yet")` — first occurrence wins.
Adding a cross-reference elsewhere in `CLAUDE.md` that contained that literal string (inside
backticks, which `find` does not care about) repointed both tests at the wrong section.

**What it cost:** four tests red at once. The failure messages were
`the '## What is not proven yet' section names no release in backticks` and
`the reach-probe command must appear in the section`, which read as *the section has gone stale* —
the opposite of what happened. Roughly ten minutes, and it would have been much worse landing on
somebody who had not just edited the file.

**How it was confirmed:** reverted the cross-reference wording to drop the `## ` prefix; the same
four tests went green with no other change.

**The shape:** a locator that matches the first occurrence returns a *wrong* region identically to
finding nothing, and the assertion downstream then describes the wrong region's contents as though
they were the right region's. Anchor on `\n## ` at line start, or on the heading plus its following
newline. This is the repo's own defect class — a check that looked at the wrong thing and a check
that found nothing render identically.

**Also true of:** any test in this repo that pulls a section out of a markdown file by heading text.
Not surveyed; there may be more.
