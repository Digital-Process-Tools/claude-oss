verdict (`unsafe`/`due`/`could-not-decide`/`nothing-due`) to `unsafe`/`due` (setup only)/`ranked`
(candidates + not_due)/`nothing-due`. `commands/run.md`'s Step 2 still documents and consumes the
old four-state shape verbatim (reads `next`/`blocked_on` off a payload that no longer has them for
the common due case). Deliberately not fixed in the #1405 lane: `commands/run.md` is owned by a
concurrently active lane (fix/1389) touching the same subsystem, and editing a file another lane
owns mid-flight is worse than flagging it.

next_action.py's actual output shape. Between the #1405 merge and whichever lane updates

common (something is due) case.

What the fix needs to do: read `state == "ranked"`, take `candidates[0]` by default (its `source`
names the step, same as `next` used to), and use `record_skip()` from `scripts/next_action.py` when
deliberately taking a lower-ranked candidate instead. `could-not-decide` no longer exists; a
`could-not-tell` candidate is now just one more entry in `candidates`, listed rather than blocking.
