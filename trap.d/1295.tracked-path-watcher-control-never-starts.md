Release v0.29.0 gate 3, round 1 audit (token 3e96e2b2f6e6d380), class B finding, non-blocking
(misreports). tests/test_skill_phase_split.py::test_the_two_isolated_control_tests_never_touch_
the_real_tracked_directory constructs root_scratch_guard._TrackedPathWatcher(...), runs the two
isolated tests inline, then calls _poll_once_for_test() once, AFTER both have finished. It never
calls watcher.start(). _DirectoryWatcher.__init__ takes a baseline snapshot at construction and
_poll_once only records names absent from that baseline -- a file created and deleted between
construction and the single poll is invisible, which is exactly the create-then-delete shape the
two tests it polices use (fake.write_text(...) ... finally: fake.unlink()). The docstring claims
this "reuses that watcher directly ... so this is a proof against the same detector CI runs" -- the
detector CI actually runs is the continuously-polling session watcher (_poll at 5ms, started in
pytest_sessionstart), not this one-shot snapshot-then-single-poll construction. Reasoned, not
observed: reverting either test to its pre-#1293 real-root write and rerunning this control would
settle it (predicted not to redden, though the session-level _phase_watcher still would). Worth
either calling watcher.start() before the inline test runs, or renaming the test so it does not
claim to be the same detector.
