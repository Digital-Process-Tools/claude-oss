Self-review auditor spawn on #1511/#1516/#1521 (PR fixing bin/oss-workspace's
step progression) flagged a new non-ASCII glyph, the ellipsis `…` (U+2026)
added by the new `oss_step_begin()` function, as a potential
`UnicodeEncodeError` risk on a Windows console defaulting to cp1252 --
matching the crash class this launcher's own comments (around the
watch-name-derivation code) explicitly name and engineer around for
Python-emitted text via `ascii()`-by-construction.

Checked directly: `'…'.encode('cp1252')` succeeds (`b'\x85'` -- cp1252 maps
byte 0x85 to U+2026 HORIZONTAL ELLIPSIS). So the specific character this
diff added is NOT new exposure; the auditor's finding was argued down on
that narrow point in the pull request.

But two glyphs `oss_step()` ALREADY used, unchanged by this diff --
`▸` (U+25B8 BLACK RIGHT-POINTING SMALL TRIANGLE) and `✓` (U+2713 CHECK
MARK) -- both FAIL to encode in cp1252:

    '▸'.encode('cp1252')  # UnicodeEncodeError
    '✓'.encode('cp1252')  # UnicodeEncodeError

Neither is new to this diff (both predate it, in the same `oss_step()`
function this diff only prefixed with `\r`), so fixing them is out of this
lane's scope. But the class is real and, per the auditor's own read,
genuinely unranked in `skills/manager/phases/findings.md`'s table -- not
`misreports`, not `fails-to-preserve`, a runtime crash that is neither data
loss nor disclosure nor a wrong report. CI's `shell` job only runs
`shellcheck`/`bash -n` on ubuntu-latest; nothing in the matrix exercises
this launcher's actual TTY-gated printf on a Windows console, so no leg
would ever catch this at all.

Whether this has ever actually crashed a real Windows console session in
practice (git-bash/mintty and Windows Terminal are both UTF-8-capable, so
this may be a live-but-never-triggered exposure rather than an observed
bug) was not established -- worth someone checking before deciding whether
it is worth a fix, and if so, whether the fix is `ascii()`-safe glyph
fallbacks (mirroring the Python-emitted-text convention already in this
file) or something narrower.
