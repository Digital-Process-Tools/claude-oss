Release audit (v0.38.0..HEAD, round 1) found: statusline.py's `refresh()` writes
`channel_fetched_at = previous_channel_stamp` / `doctor_fetched_at = previous_doctor_stamp`
(both `None` on a first attempt) alongside a new failure marker
(`channel_refresh_failed_at`/`doctor_refresh_failed_at = now`), but every consumer --
`doctor_check_statusline_unknowns.py:268-274` and `:383-391` -- checks
`isinstance(fetched_at, (int, float))` FIRST and returns `not-asked` ("nobody has looked
yet") before the failure marker it just wrote is ever read.

Observed with a positive control:

- `channel_cause` FIRST-FAIL -> `{'reason': 'not-asked'}`; CONTROL (identical failure, prior
  reading present) -> `{'reason': 'refresh-failed'}`
- `doctor_cause` FIRST-FAIL -> `{'reason': 'not-asked'}`; CONTROL -> `{'reason': 'refresh-failed'}`
- `_CHANNEL_EXPLAIN["not-asked"][0] == "WARN"`, `_CHANNEL_EXPLAIN["refresh-failed"][0] == "WAIT"`

So a first-ever refresh that is attempted and fails renders as "nobody has taken a
`channel:health` reading yet, run a refresh" (WARN) instead of "the last refresh was
attempted and got nothing back" (WAIT) -- and `check_statusline_unknowns`'s
`_maybe_fork_refresh` does not fire for this case either, because it only forks on
`refresh-failed`/`invalidated`, so the repeated-failure case is exactly the one where the
self-healing fork is withheld.

The board field (`refresh()`'s `document = {"fetched_at": now, ...}` at statusline.py:2926,
guarded in `gather()` by `not isinstance(board_fetched_at, ...) or board_failed_at >=
board_fetched_at`) does not have this bug and is the reference shape to copy: stamp
`fetched_at` unconditionally, or reorder the consumer's check to read the failure marker
before falling back to "not-asked".

Found by `oss:release-auditor`, v0.39.0 release audit round 1, ranking-table row
`misreports` (non-blocking, can ship behind a trap.d fragment). Confirmed by direct read of
`scripts/statusline.py` (refresh()) and `scripts/doctor_check_statusline_unknowns.py`
(both consumers), not by running the suite.
