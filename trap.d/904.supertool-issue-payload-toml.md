# `gh-issue-create:@FILE` wants TOML with `title`/`body`, not a markdown file

**Observed:** passing a plain markdown file to
`supertool 'gh-issue-create:@/path/to/issue.md'` fails with
`ERROR: failed to parse payload: Expected '=' after a key in a key/value pair (at line 1, column 7)
(expected JSON or TOML with title/body)`.

**What it cost:** one round trip. The error names the fix, so it is cheap — but it is cheap only
after you have hit it once.

**How it was confirmed:** converting the same content to
`title = '''<first line>'''` + `body = '''<rest>'''` and re-running the identical op succeeded.

**Worth knowing when you convert:** use TOML *literal* strings (`'''`), not basic strings (`"""`).
Basic strings process escapes, so a body containing `\n` inside backticks — say, when writing about
a regex or a locator — silently becomes a real newline in the published issue.

**Unjudged:** possibly this belongs upstream in supertool's own docs rather than as a rule here.
Logged rather than decided, per `/oss:curate`.
