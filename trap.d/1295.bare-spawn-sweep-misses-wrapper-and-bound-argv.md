tests/test_changelog_1157_overclaim_1170.py (new in v0.28.0..HEAD, commit ac55a99) asserts
gh_which.py's docstring claim -- "the one place this repo resolves an external binary before
spawning it" -- is currently true, via test_bare_gh_git_spawn_sweep_1165._scan_repository()
requiring zero non-allowlisted violations. It passes green. But the scanner has two structural
blind spots, both demonstrated live in the audit: it only sees inline literal argv lists in direct
subprocess.* calls, so it misses (1) a wrapper-mediated spawn -- this delta's own commit a9620c6
self-review found exactly this for scaffold.py's _run(["git", ...]) and named the blind spot in its
own commit message -- and (2) an argv bound to a local name first, which is exactly what
oss_config.py:2693 does three lines above its own subprocess.run call. The sweep vouches for a
completeness claim about the whole repository while only checking inline-literal direct calls.
Worth extending _scan_repository() to trace a wrapper function's own argv construction and to catch
a `command = [...]` binding followed by a `subprocess.*(command)` call, not just inline literals.
