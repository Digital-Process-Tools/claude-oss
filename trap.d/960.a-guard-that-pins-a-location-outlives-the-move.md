# A guard that pins where prose lives becomes a guard about where it used to live

Splitting `skills/manager/SKILL.md` twice (#958, #960) turned up the same shape six times, and it is
worth naming because every one of these tests was written correctly for the tree it was written in.

A guard has an invariant and a location. When the two are written as one assertion, moving the prose
does not break the invariant -- it silently re-points the guard at a place the subject no longer is.
Three forms of that appeared:

- **The vacuity guard that fires.** `test_the_ranking_table_is_findable_and_named` and
  `tests/test_embargo_routing.py` opened `SKILL.md` directly and went red with "no ranking table".
  This is the good case: it is loud, and it is the case `scripts/manager_docs.py` already exists for
  (`ManagerLoop`, the loop's whole prose, derived from disk). Repointing is one line.
- **The guard that inverts.** `test_the_spine_states_the_table_dispatch_rank_computes` and
  `test_dispatch_md_points_at_the_table_rather_than_restating_it` are a pair enforcing "exactly one
  copy of the dispatch table". After #960 moved it, both were still true statements about the wrong
  documents. The fix is to flip the pair, not to delete either half -- the invariant is *one copy in
  the loop's prose, naming `dispatch_rank.py`*, and which file holds it is what the move changes.
- **The guard nobody had to touch.** `scripts/checklist_skew.py` derives its skill-file coverage from
  the spine's own text with `_SKILL_FILE_RE`, so a new phase file was compared the moment the spine
  named it. That is what the other five should have looked like, and #547 is the incident that put it
  there.

**The one that could have passed vacuously instead of failing.**
`test_the_release_trigger_names_exactly_the_rows_that_block` took `text.find(TRIGGER_MARKER)` -- the
first occurrence of `marks blocking**`. The spine's own trigger sentence wrapped between "marks" and
"blocking\*\*", so the marker did not match there at all, and the check landed on
`phases/release.md`'s enumeration by accident. Reflowing that one line -- which a normal edit does --
would have moved the check onto a sentence that enumerates nothing, and it would have passed. It now
reads every occurrence, skips ones naming only a file path, and has a positive control.

Cost: about forty minutes across the two rounds, all of it in the second half of the work, and one
guard that was never going to announce the problem.

The general form, offered as a candidate rule rather than a conclusion: **a content check should name
its subject and derive its location.** `manager_docs.documents()` and `developer_docs.DeveloperBrief`
already do this for the two documents that have been split; nothing does it for a check that wants
"the file that currently holds table X", which is why `scripts/ranking_table.py` grew an ordered
`SOURCES` list instead. Whether that list is the right answer or a second copy of a question the
prose could answer for itself is a judgement for the curator, not for the lane that needed it to work.
