Observed during the 2026-09-19 triage sweep of Digital-Process-Tools/claude-oss: issue #1679 was
filed by the scheduler session of /oss:run running on a different repo (claude-supertool), into
this repo's tracker -- its own footer states as much ("filed by the scheduler session of /oss:run
on claude-supertool"). Yet it carries no `filed-by-loop` label.

The triager did not add the label itself: tag loop-initiated issues only, never one a human filed,
and the label is set by whichever filing call created the issue, not retroactively by a later sweep
reading provenance out of the body text. The triager judged this out of scope for a correction and
flagged it instead.

Worth a maintainer look: is a cross-repo filing call (one repo's loop session filing into a
different repo's tracker) going through the same code path that sets `filed-by-loop` on a same-repo
filing, or does the cross-repo path skip it? If it is a real gap, every issue filed this way will
misreport its own provenance to future dispatch/triage passes that rank on that label (dispatch
prefers non-loop issues, ranking WITHOUT filed-by-loop first) -- a misreports-shaped defect,
non-blocking, but compounding on every cross-repo filing until fixed.

cross-repo filing is missing the label, none has it. This is now a pattern, not a single instance.
