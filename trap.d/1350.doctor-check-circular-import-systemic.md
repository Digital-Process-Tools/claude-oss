Composition defect found while implementing #1350's doctor check
(`scripts/doctor_check_scheduler_processes.py`): module-scope `import doctor` inside a
`doctor_check_*.py` submodule collides with `doctor.py`'s own
`from doctor_check_X import check_X`, producing a circular ImportError when the submodule (or its
own test) is imported standalone before `doctor.py` is. Reproduced live for the new module and
confirmed pre-existing in several siblings under the same #497/#630 convention:
`doctor_check_clone_head.py`, `doctor_check_vanished_worktree.py`,
`doctor_check_stale_branches.py`, `doctor_check_branch_protection.py` -- roughly 20 modules total.
Masked in the ordinary case because every existing sibling test imports `doctor` itself first
rather than importing the submodule directly. A systemic, multi-file lazy-import fix across all
`doctor_check_*.py` modules is the shape of the eventual fix; out of scope for any single-issue
lane. Non-blocking (misreports class -- a test collection error, not a wrong runtime verdict).
