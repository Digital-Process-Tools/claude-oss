Investigating #1293's CI race (a FileNotFoundError from tests/test_skill_phase_split.py's
own real-root control file), the actual mechanism was NOT xdist collection timing as the
brief's own hypothesis guessed -- it was a genuine, reproducible TOCTOU bug in
scripts/skill_phases.py's `_undeclared_rows()`: it lists a directory (`manager_docs.
documents(root)`), then reads each listed path in a separate call (`path.read_bytes()`).
Anything that deletes a file in the window between those two calls -- here, a sibling xdist
worker's own legitimate control-file cleanup in the SAME shared, tracked directory -- makes
the second call raise uncaught. Confirmed directly against the real function with a
monkeypatch that deletes the file between the list and the read (no timing/threading needed
to prove it; it's a plain two-step race, not a rare interleaving).

Cost: finding this took reading through `manager_docs.py`, `skill_phases.py`'s `check()` and
`_undeclared_rows()`, and writing a small standalone repro script before touching any test
code -- the issue brief's own hypothesis (xdist collection racing test_content_invariants.py's
module-level snapshot) was plausible-sounding and NOT what was actually confirmed; that
hypothesis was a red herring worth ruling out explicitly rather than assuming.

Also: this exact `list-then-read` pattern is copy-pasted verbatim into
scripts/developer_phases.py's own `_undeclared_rows(root, spine)`, scanning a different
directory (agents/developer/). Same bug, same fix, applied there too in the same commit
even though nothing today writes concurrently into that directory -- worth grepping for a
second copy of a bug once the first one is confirmed, rather than assuming a pattern that
looks copy-pasted is coincidence.
