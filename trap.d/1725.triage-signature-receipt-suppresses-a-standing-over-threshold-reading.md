# triage reported not-due while its own evidence read over-threshold

`next_action.py` reported `triage` as `not-due` while its own evidence for the same
source read `"state": "over"` -- 3 of 8 open issues missing `lane-*` or `priority-*`,
against `triage_route_threshold: 0`. The reason given was the repeat-suppression
receipt: `"unchanged since the receipt already recorded (over:3)"`.

Observed on 2026-09-22 during an `/oss:run`, from a plain
`next_action.py --root . --json` read. The triage sweep was only reached because the
maintainer asked for one out loud mid-run; nothing in the scheduler's own ranking
would have reached it. The sweep then applied labels to three issues (#1689, #1690,
and #1691), so the work was real and was waiting.

The mechanism looks sound for the case it was built for -- not re-entering the same
step on every poll of an unchanged backlog -- but the receipt appears keyed on the
reading (`over:3`) rather than on whether that reading was ever actually drained. An
unlabelled issue is invisible to `select_issues_rank`, which refuses to rank without
a priority label, so a backlog that holds steady at the same count stays suppressed
and stays undispatchable for as long as the count does not move. `.oss.json`'s own
`_triage_route_threshold_note` argues exactly this ("there is no backlog size at
which waiting is correct") and sets the threshold to 0 to make the first unlabelled
issue fire the route -- which the receipt then overrides.

What is not established here: whether the receipt is supposed to clear when a sweep
runs and failed to, or whether it was never meant to clear on a count that does not
change. Either the receipt is keyed on the wrong thing, or the suppression is
correct and the `over` evidence beside a `not-due` verdict should say so rather than
rendering as a live finding nobody is routing. Both readings were available from the
one JSON blob and neither is distinguishable from it, which is itself the shape this
plugin is named after: a check that is being suppressed and a check with nothing to
say render identically here.
