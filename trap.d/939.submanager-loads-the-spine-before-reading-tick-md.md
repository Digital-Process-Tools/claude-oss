# The sub-manager loads the whole manager spine before it reads the command that orders the tick

Observed in the same transcript as the init-floor fragment
(`adaf3814-.../subagents/agent-a86de85749e693270.jsonl`, plugin cache 0.20.0). Order of the first
four tool calls:

1. `agent_role.py --write sub-manager`
2. `Skill(oss:manager)` -- loads `skills/manager/SKILL.md` whole, 21,309 tokens
3. `cat commands/tick.md` -- 955 tokens
4. board reads

So the spine is paid before the file that states the order of operations is read. Today that costs
nothing extra, because a tick reaches every phase the spine names. It forfeits the split's saving the
moment `commands/tick.md` narrows which phases a given tick enters -- the sub-manager cannot skip a
load it has already made. The same shape would appear if a tick ever gained a fast path (a board with
nothing dispatchable, say) that exits before the merge or release directives are ever consulted.

Possibly not worth a rule on its own; recorded because the ordering is invisible from inside
`agents/sub-manager.md`, which is what tells the spawn to open the skill first.
